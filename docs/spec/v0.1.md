# LARP Language Specification v0.1

Status: **design baseline; partially implemented**. See
[implementation status](../implementation-status.md) for supported features.
Date: 2026-10-17. Normative words MUST, MUST NOT, and MAY describe the target
language, not the current Rust scaffold. Changes require corresponding grammar,
diagnostic, and conformance updates. A release must identify its supported subset.

## 1. Scope and execution

A v0.1 program is one UTF-8 source file containing declarations and exactly one
`main_character` block. Declaration order does not affect name resolution;
local bindings are visible only after their initializer. There are no mutable
globals, imports, class inheritance, overloaded user functions/operators,
user-defined generic declarations, concurrency, FFI, destructors, or exception
handlers. Built-in generic types and collection operations are supported targets.

Execution is sequential and deterministic except for explicit host observations
and future I/O capabilities. Source evaluation order is left-to-right: receiver,
arguments, operands, and initializer elements. `&&` and `||` short-circuit.
Assignment evaluates its place once, then its right side. Compound assignment
reads that place once before evaluating its right side.

`main_character` returns `unit` implicitly. Normal termination exits with 0;
compile errors exit with 1; fatal runtime errors exit with 1; CLI usage errors
exit with 2. No execution follows a compilation error. Host resource exhaustion
is not a recoverable LARP result. There is no persistent heap after process exit.

## 2. Lexical and syntactic rules

[grammar.ebnf](grammar.ebnf) defines syntax; this specification adds contextual
restrictions. Whitespace and comments separate tokens; newlines do not insert
semicolons. `npc loop` and `locked_in while` are pairs of tokens, so comments
and newlines may appear between them.

- Identifiers match `[A-Za-z_][A-Za-z0-9_]*`, case-sensitive. Unicode identifiers
  are deferred; Unicode string contents are supported.
- Integers are decimal digit sequences with optional single underscores between
  digits. Leading zeroes remain decimal. Floats contain a decimal point with a
  digit on each side and/or a decimal exponent. Signs are unary operators.
  `0..10` is integer, range punctuation, integer, not a float.
- Strings use double quotes with `\"`, `\\`, `\n`, `\r`, and `\t` escapes.
  Literal newlines and unrecognized escapes are errors. No interpolation.
- `//` comments end at a newline; `/* ... */` comments do not nest.
- Source spans are half-open UTF-8 byte ranges. Human locations are 1-based
  lines and Unicode-scalar columns; LF and CRLF are accepted line endings.
  Tabs count as one source column; a renderer must expand them consistently.

Reserved syntax words are `sidequest main_character let if else return npc loop
in locked_in while goon touch_grass archetype role highkey lowkey init self new
larp as flex canon nonchalant sybau fn uses fr cap no_bitches mogg`.
Built-in type names occupy the type namespace, not the keyword namespace.
`yap`, `some`, `win`, `fumble`, `ascend`, `fraud`, `palantir`, `no_cap`,
`crashout`, `fortnine`, and `PeterThiel` are not reserved words.

Type arguments on calls use `<T,...>` immediately before `(`. The parser gives
this form priority when the contents parse as types and a closing `>` is
followed by `(`. Parenthesize comparisons to avoid this ambiguity. Shift
operators are absent, so nested type closers tokenize as separate `>` tokens.
Only `ascend` and `fraud` use explicit generic call arguments in v0.1.

Operators, lowest to highest precedence: `||`, `&&`, `== !=`,
`< <= > >= mogg`, `+ -`, `* / %`, unary `! - +`, postfix call/member/index.
Binary arithmetic and Boolean operators associate left. Equality and ordering
are non-associative: `a < b < c` and `a == b == c` are errors. `mogg` is exactly
numeric `>` with the same precedence and restrictions. Assignment is a statement,
not an expression. There are no implicit operator overloads.

## 3. Types, values, and conversions

| Type | Meaning and assignment semantics |
| --- | --- |
| `mf` | Signed 32-bit integer, copied by value |
| `unc` | Signed 64-bit integer, copied by value |
| `geeked` | IEEE 754 binary64, copied by value |
| `verdict` | Exactly `fr` or `cap` |
| `text` | Immutable UTF-8 text with value semantics |
| `unit` | No useful result; a function call returning it cannot initialize a variable |
| `mfs<T>` | Mutable homogeneous array, copied by reference |
| `hediJeans<T,N>` | Fixed-size array, copied element-wise; N is a nonnegative integer literal |
| `baddie<T>` | Tagged `some(T)` or `no_bitches`, copied according to T |
| `result<T,E>` | Tagged `win(T)` or `fumble(E)`, copied according to its payload |
| Class name | Non-null object identity, copied by reference |
| Role name | Object identity plus role dispatch table, copied by reference |
| `fn(T,...) -> U uses(...)` | Closure value with immutable captured bindings |

There is no `null`, universal `any`, implicit truthiness, numeric widening,
numeric narrowing, float/integer mixing, or automatic option wrapping.
`mf + unc` is an error even though an explicit widening would be safe.
Assignments and function calls require the same type, except declared nominal
class-to-implemented-role coercion. Generic containers are invariant.
Function effect bounds may widen, but parameter and result types are invariant.

An integer literal uses its expected integer type; without one it defaults to
`mf` and MUST fit. Float literals use `geeked` and MUST be finite. For a numeric
operator, an expected numeric type or the nonliteral operand constrains literal
operands; two nonliteral operands MUST already agree. The signed minimum literal
is allowed via unary minus even though its positive magnitude does not fit.
`let` infers from the initializer only; inference does not look at later uses.
`let x = no_bitches;`, untyped empty arrays, and unconstrained lambda parameters
are errors. APIs require parameter/result types. Lambda types may come from a
call's expected function type. Return paths of a lambda must agree.

All integer arithmetic is checked in every build. Overflow, division by zero,
and signed minimum divided by -1 abort. `%` has the sign of the dividend;
minimum `% -1` is zero. A statically evaluated invalid literal-only operation
is a compilation error. Folding MUST preserve short-circuit behavior.
`geeked` arithmetic follows IEEE 754 (including infinities and NaN); `%` is only
defined for integers. NaN compares unequal to itself and has false ordering
comparisons. Float output uses shortest round-trip decimal text, with `nan`,
`inf`, and `-inf` spellings for nonfinite values.

`==` supports equal-type scalar values, text contents, recursive fixed arrays,
options/results whose payloads support equality, and class/role identity.
Dynamic arrays and functions have no equality in v0.1. Numeric ordering requires
equal numeric types. `text + text` concatenates; other `+` uses are numeric.

`ascend<mf>(uncValue)` and `ascend<unc>(mfValue)` return
`result<T, ConversionError>`. `ConversionError` is a built-in nominal diagnostic
value with public immutable `text message`, copied by value. Identity integer conversion is also
allowed; all other source/target conversion pairs are rejected in v0.1.
`fraud<T>` uses the same conversion rules but aborts on a failed check.
Neither operation disables safety. Float conversions need a later RFC.

`fortnine` is an immutable prelude constant of type `unc`, value 49. It is not a
contextually typed literal. User declarations can shadow prelude value names;
duplicate declarations in one scope are errors. Types and values use separate
namespaces; built-in type names cannot be redefined.

## 4. Bindings, functions, and control flow

Both `mf x = 0;` and `let x = 0;` declare mutable local bindings. Initialization
is mandatory. An inner scope may shadow a binding; a duplicate in the same
scope is invalid. Function parameters are local value bindings (reference
values still refer to shared objects). A non-unit function MUST return a value
on every reachable non-aborting path. `return;` is allowed only for unit bodies.

`if` and `locked_in while` conditions MUST be `verdict`.
`npc loop (mf i in start..end)` evaluates bounds once, requires equal integer
types matching the index declaration, and iterates in ascending order over the
end-exclusive range. `start >= end` is empty. The index is read-only; advancing
past the final element MUST NOT cause a spurious overflow. `goon` is an infinite
loop. `touch_grass;` exits the nearest loop. There is no `continue` in v0.1.

Lambdas use `x => expression`, `(x,y) => expression`, or a block with explicit
`return`. Zero parameters use `() => ...`. Captures copy the current values at
closure creation; captured bindings cannot be reassigned. Captured class/array
references still allow mutation with an appropriate effect. There is no implicit
capture by reference to stack locals, and no nonlocal return from a lambda.
Calls evaluate a saved function or bound method as an ordinary closure.

`nonchalant T name = expression;` declares a read-only memoized binding whose
result type T must be a SnapshotValue (defined in section 8).
It captures only SnapshotValue bindings, by value, at declaration time. Its
initializer can have `abort` but no `read`, `write`, `observe`, or `io` effect.
Forcing evaluates once, stores the value, and reuses it; unused bindings do not
evaluate. Reentrant forcing aborts. Capturing a mutable object or reading a lazy
binding before it is initialized is rejected. A fatal initializer terminates the
program; there is no retry or recoverable lazy failure.

## 5. Objects, roles, and extensions

`archetype C : R1, R2 { ... }` declares a nominal reference class implementing
zero or more roles. No subclassing, structural class compatibility, static
members, custom property accessors, field initializers, or method overloads.
Field and method names MUST be distinct within a class. Default access is
`lowkey`; `highkey` exposes a member. Private access is permitted only in the
declaring class's method/constructor bodies. Extensions have no private access.

Every class has exactly one `init`. On all successful constructor paths every
field MUST be assigned. A field MUST be assigned before its first read.
The partially initialized `self` MUST
NOT escape, be captured, or call a method. Constructors may read/write initialized
self fields and abort; they may not perform I/O, observations, or mutate other
objects. Allocation publishes the identity only after successful initialization.
A constructor abort exposes no object. `init` has implicit `read,write,abort`
effects; no explicit constructor effect syntax is supported.

Ordinary fields are mutable. Object mutation is visible through all ordinary
aliases. Class calls dispatch statically unless the receiver has role type.
A role contains public method signatures without fields, default bodies, or
inheritance. A class implementation MUST have matching parameter/result types,
public access, and effects no larger than the role method's bound. Role dispatch
retains the same identity. There is no downcast. Role-typed scenario roots are
rejected because snapshot layout must be statically known.

`sidequest mf.doubled() -> mf { return self * 2; }` declares a concrete receiver
extension at file scope. User generic extensions are deferred. Extension lookup
uses the static receiver type. An accessible instance member of the name wins;
an inaccessible member is an access error, not a fallback. If its signature does
not match, the call is an error. Otherwise exactly one in-scope matching extension
is required. Identical receiver/name declarations are errors. All top-level
extensions in the one source file are in scope; cross-module imports are deferred.

## 6. Collections and expected errors

Array literals receive their `mfs<T>` or `hediJeans<T,N>` type from context;
otherwise nonempty literals infer `mfs<T>` from agreeing elements. A fixed literal
MUST contain N elements. Index expressions use `mf`. Negative or out-of-range
indices abort; no raw pointers or unchecked indexing. Collection length is at
most `2_147_483_647`; creation/growth beyond it aborts.

Required `mfs` operations are `size() -> mf`, `push(T) -> unit`,
`filter(fn(T)->verdict) -> mfs<T>`, `map(fn(T)->U) -> mfs<U>`,
`sorted() -> mfs<T>`, and `forEach(fn(T)->unit) -> unit`.
`filter`, `map`, and `sorted` create new arrays. Callback calls run eagerly,
left-to-right, once per element; a callback MUST NOT structurally mutate its
receiver array (checked before mutation by a runtime iteration guard, including
alias writes).
`sorted` is stable and limited to integer and text elements, using numeric or
lexicographic Unicode-scalar ordering. No float comparator is implied.
Fixed arrays have indexing and `size()`, with value writes through an lvalue.
`text.size()` returns the Unicode-scalar count as `mf`; text indexing is absent.

`some(value)`, `win(value)`, and `fumble(error)` use the expected option/result
type. Unconstrained missing type parameters are inference errors.
`option.copium(fallback)` yields its payload or fallback.
`result.cope(handler)` yields success, or calls the handler once with the error.
The fallback argument is evaluated eagerly even for `some`; use a future
explicit lazy API when needed. `cope` evaluates its handler expression eagerly
but invokes the closure only on failure. Error handlers MUST return T.
`isSome()` and `isOk()` return `verdict`. There is no unchecked unwrap or `?`
propagation syntax in v0.1. Expected errors are ordinary data, never unwinding.
`parseScore(text) -> result<mf,text>` accepts a whole signed decimal i32 string
without whitespace, separators, or a leading plus; invalid text/range yields
`fumble("invalid mf")`. Its declared effect bound is `uses()`.

`crashout(text)` never returns. `no_cap(verdict)` always checks its argument and
aborts on `cap`, including optimized builds. Fatal runtime diagnostics include a
stable code and source location; there is no user catch/recovery from them.

## 7. Effects and observation

The finite effect set is `read`, `write`, `observe`, `io`, `abort`:

| Effect | Meaning |
| --- | --- |
| `read` | Read mutable heap reachable through parameters, receiver, or captures |
| `write` | Mutate that heap; writing does not automatically authorize reads |
| `observe` | Emit explicit observational output |
| `io` | External capabilities, time, randomness, files, network, or host state |
| `abort` | May terminate with a fatal runtime error |

`sidequest f(...) -> T uses(read, abort) { ... }` declares an upper bound.
Omission means `uses(abort)`. `uses()` forbids all five semantic effects.
Mutation of uncaptured local value bindings is not a heap effect. Allocation
alone is not an observable semantic effect. Array literal construction initializes
new storage; subsequent reads or writes of that mutable array conservatively
have `read`/`write` effects in v0.1. OOM is a host
failure even in `uses()`. Integer arithmetic and checked indexing contribute
`abort` unless proven safe. `main_character` allows all effects.

Effects compose by union across every call edge, including recursion, indirect
calls, closures, and role dispatch. Implementations are checked against declared
bounds. A function type stores an effect bound; it MUST NOT be erased when the
function is passed or stored. Collection built-ins add receiver reads/writes and
the callback's bound. This is built-in effect propagation, not general user
effect polymorphism. A public higher-order function uses a fixed callback bound.

`yap(value)` has `observe` effect and returns unit, writing one formatted scalar
or text value plus LF to stdout. Integers use decimal, verdicts use `fr`/`cap`.
Printing objects/containers implicitly is not supported. `palantir(root)` is an
explicit observer available only inside a scenario. It writes a declaration-order
field report to stderr, including baseline, performed value, last claim, and
selection for fields accessible at the call site. Inaccessible fields are omitted;
observation does not bypass visibility. It returns unit and cannot export a
snapshot object.
`caught_in_4k` and richer formatting remain library/tooling proposals.

`sybau { ... }` dynamically suppresses `yap` output in its body and callees,
including nested blocks. It does not suppress palantir, compiler/runtime
diagnostics, or arbitrary I/O. Suppressed observations still carry `observe`
effect. The suppression state is restored on all exits.

## 8. Hypothetical state

### 8.1 Eligibility and environment

`larp (root) as Label { ... }` requires a definitely initialized local binding of
a concrete class type. Label is an uninterpreted identifier for reports, not a
variable lookup or type name. `self` roots, role roots, arbitrary expressions,
and nested scenarios are deferred. Every declared root field MUST be a
SnapshotValue: `mf`, `unc`, `geeked`, `verdict`, `text`, or recursively an
option/result/fixed array of SnapshotValues. The built-in immutable value type
`ConversionError` is also a SnapshotValue. Class/role references, dynamic
arrays, closures, and lazy cells are not SnapshotValues.

Entering creates baseline B and performed P, initially equal copies of all fields,
an empty selected-field set C, and an empty claim map F. The root name inside
the block is rebound to a region-qualified view of P; the outside identity is
kept for commit. Baseline means state at entry, not necessarily program startup.

Outer SnapshotValue locals may be read as immutable copies taken at entry.
Outer local reference/lazy/function bindings other than the named root cannot be read,
captured, called, or written inside. All assignments to outer bindings are
forbidden. The root binding cannot be reassigned or copied as a first-class
reference. The compiler MUST reject reading an outer alias of the root; testing
only identifier spelling on stores is insufficient.

### 8.2 Operations and calls

Root field reads/writes access P and obey normal visibility and types. Ordinary
assignment changes P only. `flex root.field = value;` also records the assigned
value in F as that field's last explicit claim. Later ordinary writes do not
erase the claim: palantir can show a discrepancy between a claim and the current
performed value. `flex` is restricted to direct visible fields of the active
root. There is no automatic recursive provenance tracking.

`canon root.field;` adds a direct accessible field to C. It neither copies its
current value nor commits immediately. Repeated selection is idempotent;
selection before assignment is legal; selecting an unchanged field is a no-op
at commit. Conditional selection is evaluated at runtime. Whole-root and nested
path selection are unsupported. There is no implicit deselection.

Value-only function/closure calls may use `observe` and `abort`, but not `io`.
Read/write calls are allowed only on the active root or with that view as their
sole reference argument, with no captured references or reference return value.
Because roots contain no references and there is no mutable global state, the
callee cannot reach unrelated heap state. Method frames receive the scenario
view as `self`; their normal field operations must target P. The compiler must
check their effect bounds and recursively preserve the view through helper calls.
If that restriction cannot be proven statically, reject the call. Eligibility
requires a transitive body summary in addition to effect flags: no reference
allocation, reference captures, escaping stores, or unverified indirect targets.
An effect bound alone is not a proof of scenario eligibility.
Role dispatch of scenario views, bound-method extraction from the root,
allocating new reference objects/arrays, and unknown host calls are forbidden.
Precomputed collection sizes and other SnapshotValues may be copied in.

### 8.3 Region typing and exits

Internally use `S_r(T)` for values produced inside scenario r, and `View_r(C)`
for its root. These qualifiers are not surface type syntax. All values produced
under r, including literals, imported value snapshots, function return values,
and results of comparisons, conservatively carry r. Operations preserve the
region; calls instantiate compatible value parameters/results in that region.
There is no implicit `S_r(T) -> T` conversion. This is scope provenance, not a
general information-flow security system or a refinement prover.

Regional locals may hold regional values. Closures created inside may capture
them but MUST NOT escape. Assignment of such values to outer locals or objects,
returning them, or storing them in external containers is forbidden. Observation
through yap/palantir is an explicit permitted escape of information. `canon`
is the only way to persist performed field values as ordinary program state.

`return` and loop exits MUST NOT cross the scenario boundary. Breaking a loop
wholly inside the block is allowed. An infinite loop never commits. No syntax
for early successful commit or recoverable scenario cancellation exists in v0.1.

### 8.4 Commit and failure

Only normal fallthrough at the closing brace commits. Define the new real state:

```text
R_next[f] = P[f] if f is in C, otherwise B[f]
```

The runtime MUST prepare/validate the complete update before modifying real
fields. It then publishes all selected values as one operation with no allocation,
callbacks, observation, or safepoints between selected writes. In the
single-threaded language, atomicity means no LARP code observes partial updates;
it is not crash durability or concurrent transaction serializability. All outside
aliases of the original identity see the new fields after completion.

A trap/abort discards P, C, and F before terminating. The real root remains B.
Already emitted `yap`/palantir output is not rolled back. An ordinary error result
does not abort or cancel a block. There is no concurrent modification, retry,
commit hook, or user callback during commit.

Independent field commits preserve declared types, not arbitrary object
invariants. If a class requires `a + b == total`, selective commit can break it.
Such classes are unsuitable roots until a validation/grouping extension exists.

### 8.5 Required example

```larp
archetype Founder {
    highkey unc valuation;
    highkey mf aura;
    init(unc valuation) {
        self.valuation = valuation;
        self.aura = 0;
    }
    highkey sidequest isMogging(mf opponent) -> verdict uses(read) {
        return self.aura mogg opponent;
    }
}

main_character {
    Founder bro = new Founder(20);
    mfs<mf> scores = [2, 4, 49];
    mfs<mf> winners = scores.filter(x => x mogg 3).map(x => x + 1);
    mf bonus = winners.size();
    larp (bro) as PeterThiel {
        flex bro.valuation = 1_000_000_000;
        bro.aura += bonus;
        canon bro.aura;
        bro.aura += 1;
        palantir(bro);
    }
    no_cap(bro.valuation == 20);
    no_cap(bro.isMogging(2));
    yap(bro.valuation);
    yap(bro.aura);
}
```

Required stdout is `20\n3\n`. The report shows valuation B=20,
P=1000000000, claim=1000000000, selected=false; aura B=0, P=3,
no claim, selected=true. Commit stores the final aura 3, not 2 at selection time.

## 9. Memory and object lifetime

The language uses managed memory. Reachable objects, arrays, closures, text,
lazy values, and scenario snapshots remain alive; unreachable cycles are
collectible. Reclamation timing is unobservable. There are no finalizers, weak
references, stack-address escapes, pointer arithmetic, or manual deallocation.
Lexical scope alone does not destroy a referenced object.

Implementation direction: non-moving traced heap with generation-checked handles,
explicit VM roots, and collection at documented allocation safepoints. Region
qualification is a compiler invariant, not a substitute for GC roots. B, P,
claims, pending commits, closure captures, and temporary call arguments MUST be
traced. Immutable text backing storage may be shared across value snapshots.

## 10. Diagnostics and conformance

Diagnostics MUST have a stable code, English explanation, primary source range,
and, when relevant, expected/found types and related source labels. A nickname
such as MOGGED is presentation only. Help MUST describe a valid correction.
`larp explain CODE` explains a known code without a source file.
Structured diagnostics are canonical; terminal rendering is a separate layer.

Reserved code families: L lexical, P parsing, N names, T types, E effects,
S scenarios, R runtime, B bytecode, C CLI. The registry is implemented in
`larp-diagnostics`; planned codes may be explained before a compiler exists.

The [corpus](../../tests/conformance/README.md) records expected compile success,
stdout, or a stable primary failure code. Active fixtures run through the real
compiler/VM in CI; pending fixtures describe unimplemented features.
A compiler must type-check dead branches as well as live ones.
Future runtime fixtures must assert both error code and source span. Executable
Rust model tests are evidence for the transition rule only, not language conformance.

## 11. Deferred changes and review gates

User generics/bounds, modules, class inheritance, arbitrary refinements,
first-class scenarios, nested scenarios, role views, scenario arrays/graphs,
explicit abort-with-result, native I/O APIs, async, native code generation,
formatting, and a language server require later specifications.

Before calling this baseline accepted, review the numeric conversion policy,
explicit effect syntax, conservative region restrictions, and selective commit's
invariant limitation. Before release, compare scenario programs against ordinary
explicit snapshots in configuration tuning and game-stat simulation. If the
block provides no clear benefit, keep the standalone language and revise the
feature rather than protecting its name.
